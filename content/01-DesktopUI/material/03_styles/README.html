3  Styles

Setting FontSize="20" on every button of an app is tedious and error-prone. A style sets properties in one place, for all controls it applies to. Avalonia styles work much like CSS: a selector picks the controls, setters set their properties.

In the labs you build StylesDemo: one window with a tab per topic.

If you search the web for help, you will often find WPF answers. WPF styles work differently (keys, TargetType, triggers); in Avalonia, look for selectors.

3.1 Styles and selectors

A style is a Style element with a Selector and one or more Setters:

<Style Selector="Button">
    <Setter Property="FontStyle" Value="Italic"/>
    <Setter Property="FontSize" Value="20"/>
</Style>

The selector Button matches every button in the style’s scope. To style only some buttons, give them a style class and add it to the selector with a dot:

<Style Selector="Button.bigText">
    <Setter Property="FontSize" Value="20"/>
</Style>
<Button Classes="bigText" Content="Create new employee"/>

An element can have several classes (Classes="bigText danger"), and code can add and remove them at runtime (myButton.Classes.Add("bigText")). The selector always needs a type in front of the class (Button.bigText, not .bigText), so that the compiler knows which FontSize the setter means.

Other useful selector parts:

Selector Matches
Button every Button
Button.bigText every Button with the class bigText
#SaveButton the element named SaveButton
StackPanel Button every Button somewhere inside a StackPanel
StackPanel > Button every Button that is a direct child of a StackPanel

3.1.1 Where styles live

Styles are collected in the Styles property of a control, and apply to that control and everything inside it:

  • <StackPanel.Styles> (or any other control): only inside that panel,
  • <Window.Styles>: in this window,
  • <Application.Styles> in App.axaml: in the whole application. The <FluentTheme/> already there is itself a large collection of styles.

Styles you want to share between several windows can also go into a file of their own and be included with <StyleInclude Source="/Styles/Buttons.axaml"/>.

TipLab 3.1: Style classes

🎯 Goal. A window with a first tab, where a style class makes two of three buttons bigger.

  1. Create the project as in Lab 1.1, named StylesDemo.

  2. In MainWindow.axaml, set Title="Styles Demo" Width="640" Height="420" and replace the text Welcome to Avalonia! with:

    <TabControl TabStripPlacement="Left">
    <TabItem Header="Classes">
        <StackPanel Margin="16" Spacing="10">
            <StackPanel.Styles>
                <Style Selector="Button.bigText">
                    <Setter Property="FontStyle" Value="Italic"/>
                    <Setter Property="FontSize" Value="20"/>
                </Style>
            </StackPanel.Styles>
            <Button Content="Create new employee"/>
        </StackPanel>
    </TabItem>
</TabControl>

    TabStripPlacement="Left" puts the tab headers on the left, so there is room for many tabs.

  3. Add two more buttons below the first: Edit employee and Edit employee activities. Then give the first two buttons the class bigText.

✅ Check. Create new employee and Edit employee are big and italic, Edit employee activities is not.

💡 Try it. Change the selector to Button and watch which buttons change. Then give a TextBlock the class bigText.

3.2 Cascading

When several styles match an element, all of them apply: their setters are merged. If two of them set the same property:

  • a style whose selector contains a class or pseudo-class beats one with only a type (Button.special beats Button, wherever they are written),
  • otherwise the style written later wins. There is no “more specific wins” rule as in CSS: TextBlock.caption.small only beats TextBlock.caption if it comes after it.

That makes variants easy. Instead of copying a style, add a second, more specific one that only changes what is different:

<Style Selector="TextBlock.caption">
    <Setter Property="FontSize" Value="30"/>
    <Setter Property="FontWeight" Value="Bold"/>
    <Setter Property="Margin" Value="0,0,0,20"/>
</Style>
<Style Selector="TextBlock.caption.small">
    <Setter Property="FontSize" Value="20"/>
</Style>
<TextBlock Classes="caption" Text="A form"/>
<TextBlock Classes="caption small" Text="A smaller form"/>

The second TextBlock matches both styles. It gets the bold weight and the margin from caption, and the font size from caption.small, which comes later.

3.3 Pseudo-classes

Controls change their look in certain states: a button is hovered or pressed, a text box has the keyboard focus. Selectors react to such states with pseudo-classes, written with a colon:

Pseudo-class The control …
:pointerover is under the mouse pointer
:pressed is being pressed
:focus has the keyboard focus
:disabled has IsEnabled="False"
:checked is checked (CheckBox, ToggleButton, …) 
<Style Selector="Button:pointerover">
    <Setter Property="FontWeight" Value="Bold"/>
</Style>

The style applies while the state lasts, and its setters are undone automatically when the state ends. Conditions are combined by writing them one after the other, without spaces: Button.save:pointerover matches only a button with the class save that is hovered.

3.4 Transitions and animations

Style changes happen instantly. To animate them, give the property a transition: from then on, every change of the property’s value is animated, in both directions.

<Style Selector="TextBox">
    <Setter Property="FontSize" Value="12"/>
    <Setter Property="Transitions">
        <Transitions>
            <DoubleTransition Property="FontSize" Duration="0:0:0.2"/>
        </Transitions>
    </Setter>
</Style>
<Style Selector="TextBox:focus">
    <Setter Property="FontSize" Value="20"/>
</Style>

The text box grows when it gets the focus and shrinks again when it loses it. There are transitions for other property types, too: ColorTransition, BrushTransition, ThicknessTransition, TransformOperationsTransition and more.

For animations with several steps, a style can contain keyframe animations. They run when the style starts to apply:

<Style Selector="Button.fade:pointerover">
    <Style.Animations>
        <Animation Duration="0:0:0.2" FillMode="Forward">
            <KeyFrame Cue="0%">
                <Setter Property="Opacity" Value="1"/>
            </KeyFrame>
            <KeyFrame Cue="100%">
                <Setter Property="Opacity" Value="0.4"/>
            </KeyFrame>
        </Animation>
    </Style.Animations>
</Style>

FillMode="Forward" keeps the value of the last keyframe after the animation has finished.

3.5 Classes from data

A style class can be switched on and off by a binding. The syntax is Classes.<name>, bound to a bool:

<CheckBox Name="WarningCheck" Content="Show as warning"/>
<TextBlock Classes.warning="{Binding #WarningCheck.IsChecked}" Text="Disk almost full"/>

While the check box is checked, the TextBlock has the class warning, and a style TextBlock.warning applies. This is how a style reacts to data: the chapter Data Binding uses the same pattern to highlight list entries, bound to a property of the data instead of a check box.

TipLab 3.5: Classes from data

  2. Add the CheckBox and the TextBlock from the section above.
  3. Write the style TextBlock.warning yourself: Foreground Red, FontWeight Bold.

✅ Check. Checking the box turns the text red and bold; unchecking it turns it back.

3.6 Resources

A resource is a named object, stored in the Resources of a control or the application and used with {StaticResource Key}. Colors are the typical example: define them once, use them everywhere.

<Application.Resources>
    <SolidColorBrush x:Key="BrandBrush" Color="DarkSlateBlue"/>
</Application.Resources>
<Setter Property="Foreground" Value="{StaticResource BrandBrush}"/>

StaticResource looks the resource up once. DynamicResource keeps watching it, which is needed when the resource can change at runtime, for example when switching between light and dark theme.

TipLab 3.6: An app-wide style

🎯 Goal. Every tab gets a title, styled once for the whole application.

  1. In App.axaml, add the BrandBrush resource from above, and below <FluentTheme /> a style for titles:

    <Style Selector="TextBlock.title">
    <Setter Property="FontSize" Value="22"/>
    <Setter Property="FontWeight" Value="SemiBold"/>
    <Setter Property="Foreground" Value="{StaticResource BrandBrush}"/>
</Style>

  2. At the top of each tab’s StackPanel, add a TextBlock with Classes="title" and the tab’s name as text.

✅ Check. All five tabs have a dark blue title, although the style is written only once.

💡 Try it. Change the color of BrandBrush and see all titles change.

3.7 Control templates

A style can only set properties that a control has. To change what a control is made of, you give it a new control template: the tree of elements that draws the control. A template for a button could be a colored Border with a TextBlock inside:

<ControlTemplate x:Key="ButtonTemplate" TargetType="Button">
    <Border Name="border" BorderBrush="Blue" BorderThickness="3" CornerRadius="3"
            Background="Azure" Padding="3" Margin="3">
        <TextBlock Margin="{TemplateBinding Padding}" Text="{TemplateBinding Content}"
                   VerticalAlignment="Center" HorizontalAlignment="Center"/>
    </Border>
</ControlTemplate>
<Button Template="{StaticResource ButtonTemplate}" Content="Templated button"/>

{TemplateBinding Content} takes the value from the button the template is applied to, so the same template works for every button text.

To style an element inside a template, the selector uses /template/:

<Style Selector="Button:pointerover /template/ Border#border">
    <Setter Property="Background" Value="LightBlue"/>
</Style>

This reads: the Border named border inside the template of a hovered Button.

3.7.1 Styling the parts of the built-in templates

The Fluent theme’s own templates have named parts, too. That matters because some states are drawn by the template, not by the button itself. A style Button:pointerover that sets Background has no visible effect: while hovered, the theme paints the template part PART_ContentPresenter with its own color. To change the hover color, style that part:

<Style Selector="Button.primary">
    <Setter Property="Background" Value="DarkSlateBlue"/>
    <Setter Property="Foreground" Value="White"/>

    <Style Selector="^:pointerover /template/ ContentPresenter#PART_ContentPresenter">
        <Setter Property="Background" Value="MediumPurple"/>
    </Style>
</Style>

The inner style is nested: ^ stands for the selector of the outer style, so the inner selector means Button.primary:pointerover /template/ ContentPresenter#PART_ContentPresenter.

To replace the look of a control type everywhere, Avalonia uses a ControlTheme instead of styles. That goes beyond this chapter.
