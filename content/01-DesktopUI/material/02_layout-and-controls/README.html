2  Layouts and Controls

A window can hold only one child. Everything else is arranged by panels: containers that decide where their children go and how big they are. This chapter introduces the panels you will use all the time, plus a few helpers around them.

In the labs you build LayoutDemo: a launcher window with one button per panel, each opening a small window where you try that panel out.

2.1 Layout basics

  • Panels (classes derived from Panel) hold any number of children. All other controls hold at most one child, usually in their Content property.
  • Panels can be nested: a Grid cell can contain a StackPanel, which contains another Grid, and so on. Real layouts are almost always nested.
  • Avoid fixed sizes. Let the panels size the controls, so the layout adapts when the window is resized or the text changes.
  • Layout runs in two passes: in the measure pass every element reports how much space it would like; in the arrange pass the panel assigns each child its final position and size.

Every control also has a few properties that tell its panel how to place it:

Property Meaning
HorizontalAlignment, VerticalAlignment Stretch (fill the available space), Left/Top, Center, Right/Bottom
Margin Space around the control: "10" on all sides, "10,5" left/right and top/bottom, "10,5,10,0" left, top, right, bottom
Padding Space inside the control, between its border and its content
Width, Height, MinWidth, MaxWidth, … Fixed or limited sizes; use sparingly
TipLab 2.1: The launcher

    This creates GridWindow.axaml and GridWindow.axaml.cs. In GridWindow.axaml, set Title="Grid" Width="620" Height="560".

2.2 Grid

A Grid arranges its children in rows and columns. Each child picks its cell with the attached properties Grid.Row and Grid.Column (both start at 0, which is also the default). Several children may share a cell; the one declared later is drawn on top.

<Grid ShowGridLines="True">
    <Grid.RowDefinitions>
        <RowDefinition/>
        <RowDefinition/>
    </Grid.RowDefinitions>
    <Grid.ColumnDefinitions>
        <ColumnDefinition/>
        <ColumnDefinition/>
        <ColumnDefinition/>
    </Grid.ColumnDefinitions>
    <Button Grid.Row="0" Grid.Column="1" HorizontalAlignment="Center">Button 1</Button>
    <Ellipse Grid.Row="1" Grid.Column="2" Fill="Beige"/>
    <Button Grid.Row="1" Grid.Column="2" HorizontalAlignment="Center"
            Background="Transparent">Button 2</Button>
</Grid>

This grid has two rows and three columns. Button 2 sits on top of the beige ellipse in the same cell. ShowGridLines draws the cell borders; it is a debugging aid, remove it when the layout is done.

The row and column definitions can also be written as a compact attribute:

<Grid RowDefinitions="*,*" ColumnDefinitions="*,*,*">

2.2.1 Sizing rows and columns

Every row height and column width is one of three kinds:

  • a fixed size in pixels: Width="100",
  • Auto: as big as the content needs,
  • star (*): a share of the remaining space. * and 2* split it 1 : 2. A definition without a size counts as *.
<Grid ColumnDefinitions="100,Auto,*,2*">

The first column is always 100 pixels wide, the second fits its content, and the third and fourth share the rest in the ratio 1 : 2, growing and shrinking with the window.

2.2.2 Spanning cells

Grid.RowSpan and Grid.ColumnSpan let a child cover several rows or columns, like rowspan/colspan in an HTML table:

<Label Grid.Row="4" Grid.ColumnSpan="2" Content="Rectangles showing column width"/>

2.3 StackPanel

A StackPanel puts its children one after another, vertically by default or horizontally with Orientation="Horizontal". Spacing adds a gap between them.

<StackPanel Background="Aquamarine">
    <TextBlock Text="First name"/>
    <TextBox/>
    <TextBlock Text="Last name"/>
    <TextBox Width="100" HorizontalAlignment="Left"/>
</StackPanel>

In a vertical StackPanel every child is as wide as the panel, unless it sets its own width and alignment like the second TextBox.

TipLab 2.4: StackPanel

  1. Create StackPanelWindow (title StackPanel, 420 × 380) and its launcher button, as in Lab 2.1.
  2. Replace the window’s text with the StackPanel example, and give the panel a Margin="16".

✅ Check. A turquoise block with the two labels and input fields, the second field only 100 pixels wide.

💡 Try it. Set Orientation="Horizontal". What happens to the first TextBox, which has no width of its own? Add Spacing="8".

2.4 DockPanel

A DockPanel attaches each child to one of its edges with the attached property DockPanel.Dock (Top, Bottom, Left, Right). The order matters: each child is docked into the space the previous children left over. With LastChildFill="True" (the default), the last child fills whatever remains.

In the direction it is docked, a child only gets the size it asks for. A button docked to the top is therefore only as tall as its text, even with VerticalAlignment="Stretch"; give it a Height to make it taller (a Width for Left/Right). Along the edge, Stretch fills the full length.

TipLab 2.5: DockPanel

🎯 Goal. Five buttons docked to different edges.

  1. Create DockPanelWindow (title DockPanel, 420 × 320) and its launcher button.

  2. Replace the window’s text with a DockPanel and its first two buttons:

    <DockPanel Margin="16">
    <Button DockPanel.Dock="Top" Background="LightBlue" Height="50"
            HorizontalAlignment="Stretch"
            HorizontalContentAlignment="Center" VerticalContentAlignment="Center">Button1</Button>
    <Button DockPanel.Dock="Left" Background="LightGreen" Width="90"
            VerticalAlignment="Stretch"
            HorizontalContentAlignment="Center" VerticalContentAlignment="Center">Button2</Button>
</DockPanel>

    HorizontalContentAlignment/VerticalContentAlignment center the text inside the larger button.

  3. Add three more buttons yourself:

    • Button3, docked Right, LightCoral, 90 wide,
    • Button4, docked Top, LightYellow, 50 tall,
    • Button 5, not docked, LightGray, stretched in both directions.

✅ Check. Button1 spans the full width at the top. Button4 is also at the top, but only between Button2 and Button3, because it came later. Button 5 fills the middle.

💡 Try it. Move Button1 below Button2 in the XAML. Then set LastChildFill="False".

2.5 WrapPanel

A WrapPanel works like a horizontal StackPanel, but starts a new line when the next child doesn’t fit any more. A StackPanel would simply let it run off the edge. With Orientation="Vertical" it fills columns instead of lines.

TipLab 2.6: WrapPanel

🎯 Goal. Nine buttons that wrap when the window gets narrow.

  1. Create WrapPanelWindow (title WrapPanel, 380 × 360) and its launcher button.
  2. Replace the window’s text with a <WrapPanel Margin="16"> containing nine buttons, Button1 to Button9.

✅ Check. The buttons fill a line, then continue on the next one. Make the window narrower and wider: the lines re-flow.

💡 Try it. Set Orientation="Vertical" and resize the window again.

2.6 Canvas

A Canvas doesn’t arrange anything: you position every child yourself, with the attached properties Canvas.Left, Canvas.Top, Canvas.Right and Canvas.Bottom. It is the only panel that works with coordinates. That makes it right for drawings and diagrams, and wrong for forms: nothing adapts when the window or the text size changes.

<Canvas>
    <TextBlock Canvas.Top="10" Canvas.Left="10" Text="First name"/>
    <TextBox Canvas.Top="30" Canvas.Left="10" Width="200"/>
</Canvas>
TipLab 2.7: Canvas

2.7 UniformGrid

A UniformGrid is a grid whose cells all have the same size. You don’t place the children; they fill the cells in order. Rows and Columns fix the number of rows or columns; the other number follows from the number of children.

TipLab 2.8: UniformGrid

🎯 Goal. Six buttons of equal size in two rows.

  1. Create UniformGridWindow (title UniformGrid, 360 × 320) and its launcher button.

  2. Replace the window’s text with:

    <UniformGrid Margin="16" Rows="2">
    <Button HorizontalAlignment="Stretch" VerticalAlignment="Stretch"
            HorizontalContentAlignment="Center" VerticalContentAlignment="Center">Button1</Button>
</UniformGrid>

  3. Add Button2 to Button6 the same way.

✅ Check. Two rows of three buttons, all of the same size, filling the window.

💡 Try it. Replace Rows="2" by Columns="2", then remove one button.

2.8 GridSplitter

A GridSplitter is a bar in a Grid that the user can drag to change the width of columns (or the height of rows) at runtime. Two properties matter:

  • ResizeDirection: always set it explicitly, to Columns or Rows.
  • HorizontalAlignment (for columns) decides which columns change: Left changes the splitter’s column and the one before it, Right its column and the one after it, and Stretch (the default) the columns on both sides of it. A splitter in the first column therefore needs HorizontalAlignment="Right"; without it, it tries to resize a column before column 0, and dragging does nothing.

MinWidth/MaxWidth on a ColumnDefinition limit how far the user can drag.

TipLab 2.9: GridSplitter

🎯 Goal. A grid whose column width can be changed with the mouse.

  1. Create GridSplitterWindow (title GridSplitter, 420 × 360) and its launcher button.

  2. Replace the window’s text with a <Grid Margin="16"> of two rows and two columns. Put <Button Content="Button 1" Margin="10"/> into the top-left cell and Button 2 into the bottom-right cell.

  3. Add the splitter at the end of the grid:

    <GridSplitter Grid.Column="0" Grid.RowSpan="2" Width="9" Background="Gray"
              ResizeDirection="Columns" HorizontalAlignment="Right"/>

✅ Check. A gray bar runs down the right edge of the left column. Dragging it makes the left column wider or narrower.

💡 Try it. Remove HorizontalAlignment="Right" and drag again. Then add MinWidth="80" to the first column definition (you need the long form of the definitions for that).

2.9 ScrollViewer

Panels never scroll. If the content can be larger than the space available, wrap it in a ScrollViewer. It shows a vertical scrollbar when needed; the horizontal one is off unless you set HorizontalScrollBarVisibility (Auto shows it when needed, Visible always).

Two ways to break a line in a text:

  • in an attribute value, the XML character reference &#10;: Text="a&#10;b",
  • inside a TextBlock’s content, the element <LineBreak/>.

One more thing about panels: a panel only receives mouse events where it has a background. If a panel should react to clicks but not be colored, set Background="Transparent".

TipLab 2.10: ScrollViewer

🎯 Goal. Content that is wider than the window, with a scrollbar.

  1. Create ScrollViewerWindow (title ScrollViewer, 420 × 340) and its launcher button.

  2. Replace the window’s text with:

    <ScrollViewer Margin="16" HorizontalScrollBarVisibility="Visible">
    <Grid MinWidth="600" ColumnDefinitions="*,*">
    </Grid>
</ScrollViewer>

  3. In the grid’s first column, add a TextBox with Margin="10" and the text a and b on two lines. In the second column, add a TextBlock with Margin="10" whose content is a b c d e f g, a <LineBreak/>, and h i.

✅ Check. A horizontal scrollbar is shown below the content. Scroll right to see the second column.

💡 Try it. Set HorizontalScrollBarVisibility="Auto" and make the window wider than 600 pixels.

2.10 Building a UI in code

Everything you write in XAML can also be written in C#: XAML elements are objects, attributes are properties. Attached properties are set with static methods such as DockPanel.SetDock(button, Dock.Top).

var dPanel = new DockPanel();
var btnTop = new Button();
var btnLeft = new Button();

btnTop.Content = "Top Button!";
btnTop.Height = 50;
btnTop.HorizontalAlignment = HorizontalAlignment.Stretch;
btnTop.HorizontalContentAlignment = HorizontalAlignment.Center;
btnTop.VerticalContentAlignment = VerticalAlignment.Center;

btnLeft.Content = "Left Button!";
btnLeft.Width = 95;
btnLeft.VerticalAlignment = VerticalAlignment.Stretch;
btnLeft.HorizontalContentAlignment = HorizontalAlignment.Center;
btnLeft.VerticalContentAlignment = VerticalAlignment.Center;

DockPanel.SetDock(btnTop, Dock.Top);
DockPanel.SetDock(btnLeft, Dock.Left);

dPanel.LastChildFill = false;
dPanel.Children.Add(btnTop);
dPanel.Children.Add(btnLeft);

Content = dPanel;

Keep this for the rare cases where the UI is only known at runtime, for example one button per entry of a list read from a file. For everything else XAML is shorter, easier to read and shows up in the previewer.
